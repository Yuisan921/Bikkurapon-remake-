# びっくらポン（文化祭リメイク版）

回転寿司でおなじみの「びっくらポン」を、文化祭のミニゲームとして再現するプロジェクトです。

コインを入れる  
→ 画面で抽選演出  
→ 抽選結果を決定  
→ 当たり用 / はずれ用それぞれのホッパーからサーボモーターでカプセルを排出  
→ 結果を画面に表示

という一連の流れを実装しています。

**どちらの結果でも必ずカプセルが1個出ます。**

- 当たり → 当たり用ホッパーから景品カプセルを排出
- はずれ → はずれ用ホッパーから参加賞カプセルを排出

という2ホッパー構成です。

---

# クイックスタート（まずはこれだけ）

## PC側について

このプロジェクトの `.exe` は、一般的な単体アプリとは少し仕組みが異なります。

**パソコンの中で小さなWebサーバーを起動し、その画面をブラウザで表示する方式です。**

ブラウザだけでは、USB接続されたArduinoやコインセンサー、サーボモーターと直接通信できないため、必ず `.exe` を起動した状態で使用します。

逆に言えば、`.exe` が起動していれば、

- ゲーム演出
- 抽選
- 在庫管理
- Arduinoとの通信
- 管理画面

などはすべて自動的に動作します。

## 起動手順

1. `BikkurapoSetup.exe` をインストールする  
   入手方法は後述の「インストーラーを使う」を参照してください。

2. スタートメニューまたはデスクトップの「びっくらポン」を起動する

3. 裏側でサーバーが起動し、自動で次の2つのウィンドウが開きます。

   - **演出画面**
   - **管理画面**

4. 普段のテストでは通常のウィンドウ表示になります。

   文化祭当日に外部モニターへフルスクリーン表示したい場合は、`config/settings.json` の `kiosk_mode` を `true` にしてください。

5. 演出画面右下にある「コインを投入（テスト用）」ボタンを押すと、Arduinoを接続していなくても抽選演出から結果表示まで確認できます。

6. Arduino UNOまたはUNO互換ボードをUSBでノートPCに接続すると、実際のコインセンサーからゲームを開始できるようになります。

   通常はシリアルポートを自動検出します。

   うまく認識されない場合は、`config/settings.json` の `serial_port` に、

   ```json
   "serial_port": "COM3"
```

のようにCOMポートを手動指定してください。

7.  景品、確率、在庫などを変更する場合は `config/prizes.json` を編集します。

## 困ったとき

次の順番で確認すると原因を切り分けやすくなります。

1.  演出画面右下のテストボタンでソフト単体が動くか
2.  `/admin` で在庫が正常に表示されるか
3.  ArduinoがWindowsでCOMポートとして認識されているか
4.  Arduino IDEのシリアルモニターでコイン投入が検知されているか
5.  サーボがArduino単体で正常に動くか

# 全体構成（役割分担）

本体は主に次の2つの機器で構成されています。

## ノートPC

抽選ロジックと画面表示を担当します。

主な役割は次の通りです。

-   抽選処理
-   景品在庫管理
-   演出画面表示
-   管理画面表示
-   ArduinoとのUSBシリアル通信
-   排出予約
-   排出完了確認
-   データ保存

PC側からGPIOなどを直接操作することはありません。

## Arduino UNO / UNO互換ボード

ハードウェア制御を担当します。

主な役割は次の通りです。

-   コインセンサー入力
-   コイン投入検知
-   当たり用サーボ制御
-   はずれ用サーボ制御
-   ノートPCとのUSBシリアル通信
-   カプセル排出完了通知

文化祭本番では、

**Arduino UNO / UNO互換ボード + USB接続**

を標準構成として使用します。

# 通信の流れ（USB版）

Arduino UNO版とXIAO USB版では、PCとの通信方式を共通化します。

## 1. コイン投入

Arduinoがコインセンサーの投入を検知します。

ArduinoからPCへ、

```
COIN:<番号>
```

を送信します。

例：

```
COIN:1
```

----------

## 2. PC側で抽選

PC側で景品を抽選します。

この時点では、まだ在庫は確定して減らしません。

排出対象がある場合、PCからArduinoへ、

```
DISPENSE:<coinId>:<reservationId>:<hopper>
```

を送信します。

例：

```
DISPENSE:1:abc123:A
```

`hopper` は、

-   `A` → 当たり用ホッパー
-   `B` → はずれ用ホッパー

を表します。

----------

## 3. Arduinoがカプセルを排出

Arduinoは指定されたホッパーのサーボモーターを動かします。

実際にカプセルを排出します。

----------

## 4. 排出完了通知

サーボ動作が完了したら、ArduinoからPCへ、

```
DONE:<reservationId>
```

を返します。

例：

```
DONE:abc123
```

----------

## 5. 在庫確定

PCは `DONE` を受信して初めて在庫を1個減らします。

その後、ゲーム画面へ抽選結果を通知します。

この方式により、

-   USBケーブルが途中で抜けた
-   Arduinoが応答しなかった
-   サーボ排出処理が開始できなかった
-   通信がタイムアウトした

といった場合に、実際には景品が出ていないのに在庫だけ減る事故を防ぎます。

失敗した予約はキャンセルされます。

----------

# カプセル排出機構（CAD）

`cad/capsule_dispenser.scad` に、縦型180度ローター式のパラメトリックモデルがあります。

OpenSCADで編集できます。

## 基本構造

ローターには上下180度対向のU字型ポケットが2個あります。

1.  上側のポケットへカプセルが1個入る
2.  ローターを180度回転させる
3.  カプセルが下側へ移動する
4.  排出口からカプセルが落ちる
5.  同時に反対側の空ポケットが上へ移動する
6.  次のカプセルが装填される

という構造です。

ローター回転中はケースの円形内壁がポケットの開口部を塞ぐため、後続のカプセルが一緒に落ちにくい構造になっています。

当たり用・はずれ用で同じ排出機構を2セット使用します。

## カプセルサイズ

既定値は、

```
capsule_diameter = 48mm
```

です。

実際に使用するカプセルをノギスなどで測定し、必要に応じて変更してください。

例えば、

-   45mm
-   48mm
-   50mm
-   65mm

などに対応できます。

## STL出力

OpenSCADでファイルを開き、冒頭の `PART` を切り替えます。

主なパーツは、

```
"rotor"
"housing"
"front_plate"
"rear_plate"
"hopper_adapter"
"outlet_adapter"
```

です。

それぞれ個別にSTLへ出力します。

```
"assembly"
```

は組み立て確認用です。

STL出力用ではありません。

`ROTOR_PREVIEW_ANGLE` を、

```
0
```

または、

```
180
```

へ変更すると、ローターの2つの停止位置を確認できます。

## 3Dプリンタサイズ

48mmカプセル設定の場合、ケース外形は約160×160mmです。

一般的な、

```
200mm × 200mm
```

クラスの3Dプリンタへ収まる想定です。

## 組み立て

1セットにつき、

-   ローター
-   ケース
-   フロントプレート
-   リアプレート
-   ホッパーアダプター
-   排出口アダプター

を印刷します。

前後プレートとケースはM4通しボルト4本で固定します。

ローター前面はサーボホーンへ固定します。

ローター後面の軸は `rear_plate` で支持します。

サーボホーンの穴位置は製品によって異なるため、

```
horn_*
```

系パラメータを実物に合わせて調整してください。

# サーボの動作方式

現在の180度ローター構造では、

```
0度
↓
180度
↓
0度
↓
180度
...
```

のように、排出するたびに2つの停止位置を交互に使用する方式が適しています。

排出後に毎回元の位置へ戻さないことで、ローターの1回転分の移動を減らし、排出時間を短縮できます。

ただし、実際のサーボでは0度・180度ぎりぎりまで動かすと機械的に負荷が掛かることがあります。

そのため実機では、

```
5度
```

と、

```
175度
```

などに調整してください。

**注意：既存のXIAO USB版ファームウェアが往復方式になっている場合は、CADの180度交互停止方式に合わせてファームウェア側の動作も調整してください。**

Arduino UNO版では、実際の排出機構に合わせて角度を調整してください。

# ホッパー

背の高いカプセル貯留部分は3Dプリントしません。

代わりに、

-   透明アクリルパイプ
-   PET素材の筒
-   透明容器
-   自作ホッパー

などを `hopper_adapter` へ接続します。

48mmカプセルの既定設定では、通路内径は約51.5mmです。

カプセルが単列で流れるようにしてください。

途中で2個が横並びになる構造にすると、詰まりやすくなります。

また、入口直前へ大量のカプセル重量が集中するとローターへ強い力が掛かり、噛み込みが起きる可能性があります。

必要に応じて傾斜板などを設け、ローターへ直接大きな荷重が掛からない構造にしてください。

----------

# サーボモーター

景品入りカプセルを180度移動させるため、SG90のような小型サーボよりも、

**MG996R相当の金属ギア・高トルクサーボ**

を推奨します。

必要数は、

```
2個
```

です。

-   当たり用 ×1
-   はずれ用 ×1

# サーボ電源について

**サーボ2個をArduino UNO本体の5V端子から直接駆動することは推奨しません。**

サーボは動作開始時や負荷が掛かった際に大きな電流を消費します。

Arduino側の5Vから直接供給すると、

-   電圧降下
-   Arduinoの再起動
-   USBシリアル切断
-   PCとの通信エラー
-   サーボの振動
-   誤動作

などが発生する可能性があります。

サーボには、十分な容量を持つ外部5〜6V電源を使用してください。

配線イメージ：

```
ノートPC
   │
   │ USB Type-B
   ▼
Arduino UNO
   │
   ├── D9  ─────────→ 当たりサーボ 信号線
   │
   └── D10 ─────────→ はずれサーボ 信号線


外部5〜6V電源
   │
   ├── +5〜6V ──────→ 当たりサーボ VCC
   │                └→ はずれサーボ VCC
   │
   └── GND ─────────→ 当たりサーボ GND
         │           └→ はずれサーボ GND
         │
         └──────────→ Arduino GND
```

**Arduinoと外部サーボ電源のGNDは必ず共通にしてください。**

# Arduino UNO配線

## 基本配線

部品

Arduino UNO

コインセンサー信号

D2

当たり用ホッパー サーボ信号

D9

はずれ用ホッパー サーボ信号

D10

GND

GND

D0とD1はUSBシリアル通信で使用されるため、通常は使いません。

## コインセンサー

コインセンサーは、

**投入時にLOWになる構成**

を想定しています。

Arduino側では、

```
pinMode(COIN_SENSOR_PIN, INPUT_PULLUP);
```

を使用します。

そのためテスト時には普通のスイッチでも代用できます。

```
Arduino D2
   │
   └── スイッチ ── GND
```

スイッチを押すとLOWになり、コイン投入として扱われます。

```
Run workflow
```

# 設定ファイルの保存場所

設定フォルダの場所は、実行ファイルの場所へ書き込み可能かどうかによって変わります。

例えば、

```
C:\Program Files\
```

のような一般ユーザーが書き込めない場所へインストールした場合は、

```
%LOCALAPPDATA%\Bikkurapon\config\
```

へ設定ファイルが作成されます。

在庫データも、

```
%LOCALAPPDATA%\Bikkurapon\data\
```

側へ保存されます。

現在使用している設定フォルダは、起動時のコンソールにも、

```
設定フォルダ: ...
```

として表示されます。

# インターネットなしのルーター / APでWi-Fi版を使用する

Wi-Fi版はインターネット接続自体は必要ありません。

ノートPCとESP32が同じLAN内にいれば通信できます。

## 手順

1.  ルーターのDHCPを有効にする
    
2.  ノートPCとESP32を同じSSIDへ接続する
    
3.  ゲストWi-FiやAP分離機能は使用しない
    
4.  Windowsで、
    
    ```
    ipconfig
    ```
    
    を実行する
    
5.  ノートPCのIPv4アドレスを確認する
    
6.  ESP32の `SERVER_URL` を、
    
    ```
    http://<PCのIP>:5000/api/insert_coin
    ```
    
    に設定する
    
7.  PCの `settings.json` で、
    
    ```
    "host": "0.0.0.0",
    "allow_remote_insert_coin": true
    ```
    
    を有効にする
    
8.  Windowsファイアウォールの確認が表示されたら、プライベートネットワークを許可する
    

Socket.IOなど、画面表示に必要なライブラリも、

```
static/vendor/
```

から読み込むため、WAN側のインターネット接続は不要です。

USB版ではこの設定は必要ありません。

# 景品・確率のカスタマイズ

景品設定は、


を編集します。

-   当たり
-   はずれ

例：

```

  "name": "当たり",
  "probability": 0.2,
  "stock": 30,
  "hopper": "a"
}
```

当選確率です。

例：

```

```

なら20%です。

各景品の確率合計が、

```

```

になるように設定してください。

初期在庫数です。

例：

```
"stock": 30
```

なら30個です。

```
"stock": null
```

にすると在庫無制限として扱います。

# hopper


→ 当たり用

```

```


→ カプセルを排出しない

という意味です。

# 在庫切れになった景品

----------

# 全景品の在庫がなくなった場合

全景品の在庫がなくなると、抽選はエラー扱いになります。

この場合、

-   カプセルを排出しない
-   在庫を減らさない
-   マイコンへ排出なしを通知
-   演出画面を在庫切れ表示へ変更

します。

演出画面には、

```
巫女さんを呼んでください
```

と表示されます。

管理画面から在庫を補充すると、自動的に通常の待機画面へ戻ります。

在庫切れ中にコインを投入した来場者への対応は、スタッフ側でメダル返却などを行う想定です。

`stock: null` の景品を1つ用意しておけば、全在庫切れ状態にはなりません。

----------

# 初期在庫を変更した場合

`config/prizes.json` の初期在庫を変更しても、既に、

```
data/stock.json
```

が存在する場合は現在在庫が優先されます。

初期在庫から作り直したい場合は、

```
data/stock.json
```

を削除してからアプリを再起動してください。

----------

# インストーラーを入れ直しても景品設定が変わらない場合

インストーラーは、既にユーザー設定ファイルが存在する場合、それをできるだけ維持します。

そのため、古いバージョンの、

```
config/prizes.json
```

が残っていると、新しい `.exe` に入れ替えても設定が変わらない場合があります。

設定フォルダは通常、

```
%LOCALAPPDATA%\Bikkurapon\config\
```

です。

必要に応じて、

```
prizes.json
```

を確認してください。

古い既定形式を検出した場合は、

```
prizes.json.bak
```

としてバックアップを作成してから新しい形式へ差し替える処理があります。

完全に初期化したい場合は、アプリ終了後に既存の `prizes.json` を削除してから再起動してください。

# 推奨する本番構成

最終的な推奨構成は次の通りです。

```
                   ┌─────────────────┐
                   │    外部モニター   │
                   │   ゲーム演出表示   │
                   └────────▲────────┘
                            │ HDMI等
                            │
┌───────────────────────────┴────────┐
│              ノートPC               │
│                                    │
│ Flask + Socket.IO                  │
│ 抽選                               │
│ 在庫管理                           │
│ 演出画面                           │
│ 管理画面                           │
│                                    │
└────────────────┬───────────────────┘
                 │
                 │ USB Type-B
                 ▼
        ┌─────────────────┐
        │   Arduino UNO    │
        │                  │
        │ D2  コイン入力   │
        │ D9  当たりServo  │
        │ D10 はずれServo  │
        └───┬──────┬──────┘
            │      │
            │      │
       ┌────▼─┐  ┌─▼────┐
       │当たり│  │はずれ │
       │Servo │  │Servo  │
       └──────┘  └───────┘
            ▲        ▲
            │        │
            └────┬───┘
                 │
          外部5〜6V電源
```

コイン投入から景品排出まで、

```
コイン投入
↓
Arduinoが検知
↓
PCへCOIN送信
↓
PCで抽選
↓
ArduinoへDISPENSE送信
↓
サーボ動作
↓
カプセル排出
↓
ArduinoからDONE
↓
在庫確定
↓
結果表示
```

という流れになります。
