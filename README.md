# びっくらポン(文化祭リメイク版)

回転寿司でおなじみの「びっくらポン」を文化祭のミニゲームとして再現するプロジェクトです。

コインを入れる → 画面で抽選演出 → 結果表示 → 当たり用/はずれ用それぞれの
ホッパーからサーボモーターでカプセルを排出、という一連の流れを実装しています。
**どちらの結果でも必ずカプセルが1個出ます**(当たりは良い景品、はずれは
参加賞的な景品、という2ホッパー構成です)。

## クイックスタート(まずはこれだけ)

**「.exe」は普通のアプリではなく、パソコンの中で小さなWebサーバーを
動かして、それをブラウザで表示する仕組みです。** ブラウザだけでは
USB(コインセンサー・サーボ)と通信できないので、必ず.exeを起動した
状態でブラウザを使います(逆に言うと、.exeさえ動いていれば操作は
全部ブラウザ上で完結します)。

1. `BikkurapoSetup.exe` をインストールする(入手方法は下記「インストーラーを使う」参照)
2. スタートメニュー/デスクトップの「びっくらポン」をクリックする
   → 裏側でサーバーが起動し、自動で **演出画面**(黒背景)と
   **管理画面**(表形式)の**2つの別ウィンドウ**(タイトルバーあり、動かせます)が開く。
   文化祭当日にフルスクリーン表示したい場合は `kiosk_mode` を有効にしてください
   (下記「演出画面・管理画面の自動起動について」参照)
3. 演出画面の右下にある「コインを投入(テスト用)」ボタンを押すと、
   抽選演出〜結果表示までを試せる(XIAO ESP32-C3が無くてもここまで確認できる)
4. XIAO ESP32-C3をUSBでノートPCに挿すと、実際のコインセンサーの投入でも
   同じ抽選が動くようになる(ポートは自動検出。うまくいかない場合は
   `config/settings.json` の `serial_port` を手動指定)
5. 景品や確率を変えたいときは `config/prizes.json` を直接編集する
   (詳しくは「景品・確率のカスタマイズ」参照)

困ったら: 演出画面右下のテストボタンで「ソフト単体」が動くか、
`/admin` で在庫が見えるか、を切り分けると原因を絞りやすいです。

## 全体構成(役割分担)

本体は2つの機器に分かれています。

- **ノートPC**: 抽選ロジックとモニター表示画面を担当(このリポジトリのFlaskアプリ)。
  GPIOなどのハードウェアは一切触らない
- **Seeed XIAO ESP32-C3**: コインセンサーと、当たり用・はずれ用それぞれの
  カプセル排出サーボモーター(計2個)を直結し、コイン投入を検知したら
  ノートPCに通知するだけの小さなファームウェアを書き込んで使う

ESP32とノートPCの接続方法は **USBケーブル(推奨)** と **WiFi** の2通りを用意しています。
画面用のライブラリもアプリに同梱しているため、どちらもインターネット接続は不要です。
WiFi版は、インターネットにつながっていない家庭用ルーター/APでも、ノートPCと
ESP32が同じLAN内にいれば動作します。

| 接続方法 | ファームウェア | 特徴 |
| --- | --- | --- |
| USB(推奨) | `firmware/xiao_esp32c3_usb_serial/` | ケーブル1本で完結。会場のWiFi環境に左右されず安定動作 |
| WiFi | `firmware/xiao_esp32c3_wifi_http/` | ESP32を離れた場所に置きたい場合向け。会場WiFiかノートPCのモバイルホットスポットが必要 |

### 通信の流れ(USB版)

1. XIAO ESP32-C3がコインセンサーの投入を検知し、USBシリアルで一意な番号付きの
   `COIN:<番号>` を送る
2. ノートPCが景品を予約し、予約番号付きの `DISPENSE` 命令を返す。この時点では
   在庫ファイルと当選画面はまだ確定しない
3. ESP32が対応するサーボモーターを動かし、動作完了後に `DONE:<予約番号>` を返す
4. ノートPCが完了応答を確認して初めて在庫を1個減らし、ブラウザへ当選結果を通知する。
   タイムアウト・USB切断・失敗応答の場合は予約を取り消し、在庫を減らさない

WiFi版も同じく、排出後に完了ACKをHTTPで返してから在庫を確定します。詳しくは
`firmware/xiao_esp32c3_wifi_http/xiao_esp32c3_wifi_http.ino` 冒頭のコメントを参照してください。

## カプセル排出機構(CAD)

`cad/capsule_dispenser.scad` に、回転ゲート式のカプセルディスペンサーの
パラメトリックモデル(OpenSCAD)があります。当たり用・はずれ用(弱景品)で
同じものを2セット印刷して使う想定です。

- 無料の [OpenSCAD](https://openscad.org/) で開いてください
- ファイル冒頭の `PART` 変数を `"throat_adapter"` / `"gate_disc"` / `"base"` に
  切り替えて、それぞれ File > Export > Export as STL でパーツごとに出力します
  (`"assembly"` は組み立てイメージのプレビュー用で、STL出力の対象ではありません)
- `capsule_diameter`(カプセル直径)や `servo_*`(サーボの寸法)は実物に
  合わせて数値を調整してから出力してください
- レンダリング時にコンソールへ各パーツの高さ・直径が出力されるので、
  お使いの3Dプリンタの造形サイズ(`printer_bed_x/y/z`)に収まっているか
  確認してください(既定値は200x200x170mm)
- FusionなどのCADで外側の筐体(装飾込みの本体ケース)を作る場合は、
  この機構部分だけOpenSCADでSTLを出力し、そのSTLをメッシュとして
  Fusion側のプロジェクトに取り込んで組み合わせる形がおすすめです

### カプセルを貯める部分(ホッパー)は3Dプリントしない

カプセルをまとめて貯めておく背の高い部分は、3Dプリンタの造形サイズに
左右されないよう、あえてOpenSCAD側では作っていません。代わりに
`throat_adapter` パーツ上部の「襟」(`funnel_collar_outer_d` で直径を調整)に、
市販の透明アクリルパイプや、いらないペットボトル・クリアな容器などを
接着 or はめ込みで取り付けて使ってください。中のカプセルが見える方が
本物のガチャガチャらしくもあります。使う容器の口の直径に合わせて
`funnel_collar_outer_d` を調整してから `throat_adapter` を出力してください。

## リポジトリの構成

- `run.py` … 起動エントリーポイント
- `app/server.py` … Flask + Socket.IO サーバー本体(ノートPCで動かす)
- `app/lottery.py` … 確率抽選と景品在庫の管理
- `app/serial_bridge.py` … XIAO ESP32-C3とのUSBシリアル通信(コイン投入受信・結果送信)
- `app/paths.py` … 通常実行/.exe実行(PyInstaller)でのパス解決の切り替え
- `app/browser_launcher.py` … 起動時に演出画面・管理画面を自動でブラウザに開く処理
- `bikkurapon.spec` … .exeビルド用のPyInstaller設定
- `installer/bikkurapon.iss` … Windowsインストーラー用のInno Setup設定
- `.github/workflows/build-windows.yml` … Windows環境で.exe/インストーラーを自動ビルドするCI
- `config/prizes.json` … 景品の一覧・当選確率・初期在庫・サーボ角度
- `config/settings.json` … ポート番号・USBシリアルポート・ブラウザ自動起動などの設定
- `templates/`, `static/` … モニター表示画面(`/`)と在庫管理画面(`/admin`)
- `data/stock.json` … 実行時に自動生成される現在の在庫数(gitignore対象)
- `firmware/xiao_esp32c3_usb_serial/` … XIAO ESP32-C3用ファームウェア(USB接続版・推奨)
- `firmware/xiao_esp32c3_wifi_http/` … XIAO ESP32-C3用ファームウェア(WiFi接続版)
- `cad/capsule_dispenser.scad` … カプセル排出機構のパラメトリックCAD(OpenSCAD)
- `scripts/` … 開発用の起動スクリプトや.exeビルドスクリプト(任意、インストーラーを使うなら不要)

## 必要なハードウェア

- ノートPC(モニター表示・抽選ロジック用)
- Seeed XIAO ESP32-C3
- コインセンサー(フォトインタラプタや簡易スイッチなど)
- カプセル排出用のサーボモーター(SG90/MG90Sなど)× **2個**(当たり用・はずれ用)
- カプセル排出機構(3Dプリント/プラダン等で自作、当たり用・はずれ用の2セット)
- 外部モニター(ノートPCの画面をそのまま使ってもOK、フルスクリーン表示推奨)
- USBケーブル(XIAO ESP32-C3をノートPCに接続する用)

### 配線例(XIAO ESP32-C3共通)

| 部品 | ピン |
| --- | --- |
| コインセンサー(入力、投入でLOW) | D0 |
| 当たり用ホッパーのサーボ(信号線) | D1 |
| はずれ用ホッパーのサーボ(信号線) | D2 |

## セットアップ

### ノートPC側 その1: インストーラーを使う(推奨)

Windowsのユーザー名に日本語(ひらがな等の非ASCII文字)が含まれていると、
バッチファイルやPythonの仮想環境まわりで文字コード関連の不具合が起きる
ことがあります。それを避けるため、GitHub Actions(クラウド上のWindows環境)
で自動ビルドした**インストーラー**を配布する仕組みを用意しています。
インストーラーはユーザー名を含まない `C:\Program Files\Bikkurapon\` に
インストールするので、この問題を回避できます。

**入手方法**

1. GitHubリポジトリの [Actions タブ](../../actions/workflows/build-windows.yml) を開く
2. 一番上(最新)のビルドを開き、Artifacts欄から `BikkurapoSetup` をダウンロードして展開する
   (`BikkurapoSetup.exe` が入っています)
3. ビルドがまだ無い/最新化したい場合は "Run workflow" ボタンで手動実行できます

**インストール・実行**

`BikkurapoSetup.exe` を実行してインストールすると、スタートメニューと
デスクトップに「びっくらポン」のショートカットができます。それをダブル
クリックするだけで、サーバー起動 → 演出画面と管理画面が別ウィンドウで
自動でブラウザに開きます(bat不要)。

設定フォルダの場所は、exeの隣に書き込めるかどうかで変わります。
`C:\Program Files\` のように一般ユーザーが書き込めない場所にインストールした
場合は、自動で **`%LOCALAPPDATA%\Bikkurapon\config\`**(エクスプローラーの
アドレス欄にそのまま貼り付けて開けます)に作られます。在庫データ(`data\`)も
同じ場所です。実際に使われている場所は、起動時のコンソールの
「設定フォルダ: ...」という行にも表示されます。設定はそのフォルダ内の
ファイルを直接編集してください。

**アンインストール**

Inno Setup製のインストーラーには、アンインストーラーが自動的に付属して
います(別途用意する必要はありません)。学校のPCなど、古いバージョンを
消してから入れ直したい場合は、以下のどちらかで削除できます。

- スタートメニューの「びっくらポン」フォルダの中にある
  「Uninstall びっくらポン」をクリックする
- Windowsの「設定」→「アプリ」→「インストールされているアプリ」で
  「びっくらポン」を探して「アンインストール」を押す

新しいバージョンを入れ直す時も、上書きインストールで問題ありません
(アンインストールは必須ではなく、古いバージョンを完全に消したい時だけ
使ってください)。

### ノートPC側 その2: .exeを自分でビルドする(Pythonのインストール不要で動く)

上記のインストーラーが使えない/中身を見たい場合は、[PyInstaller](https://pyinstaller.org/)
で単体の実行ファイルに自分でビルドすることもできます。

```
scripts\build_exe.bat
```

`dist\bikkurapon.exe` が生成されます。ダブルクリックすると、サーバー起動
と同時に演出画面・管理画面が自動でブラウザに開きます。初回起動時に、exeと
同じ場所に `config\`(景品・設定)と `data\`(在庫)フォルダが自動的に
作られるので、以降はそれらを直接編集すれば、exeを作り直さなくても景品や
確率を変更できます。

.exeは**ビルドしたOSでしか動きません**(Windows機でビルドすればWindows用、
Macでビルドすればmac用)。ビルド時にも日本語ユーザー名が原因の不具合が
起きることがあるので、その場合は上記のインストーラー(GitHub Actionsで
ビルド)を使ってください。

### ノートPC側 その2: Pythonで直接動かす(開発用)

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python run.py
```

起動時にESP32が未接続でも、アプリはバックグラウンドで接続を待ち続けます。
後からUSBケーブルを挿して `USBシリアルに再接続しました` と表示されれば利用できます。
接続しても認識されない場合は、
`config/settings.json` の `serial_port` に手動でポート名(例: `/dev/ttyACM0` や `COM3`)を
指定してください。ESP32を接続しない状態でも、ブラウザの
「コインを投入(テスト用)」ボタンで動作確認できます(本番当日は
`show_debug_button` を `false` にして、来場者が誤ってタップできないようにしてください)。

起動後、ブラウザで `http://localhost:5000/` を開くとゲーム画面が表示されます。

### 演出画面・管理画面の自動起動について

サーバー(exeまたは `python run.py`)を起動すると、`app/browser_launcher.py`が
自動で「演出画面」と「管理画面」の2つを別ウィンドウでブラウザに開きます。
手動でブラウザを開く必要はありません。

既定では**両方とも普通のウィンドウ**(タイトルバーあり)で開きます。
1台のモニターでテストする時は、タイトルバーを掴んでウィンドウ同士を
ずらしたり並べたりできて操作しやすいはずです。

- `config/settings.json` の `auto_open_browser` を `false` にすると、この
  自動起動を無効化できます(手動で `http://localhost:5000/` と `/admin` を
  開いてください)
- **文化祭当日、外部モニターにフルスクリーンでキオスク表示したい場合**は、
  `kiosk_mode` を `true` にしてください。演出画面がタイトルバーなしの
  フルスクリーンになります(操作ミスで来場者が別の画面に切り替えられない
  ようにするための表示なので、普段のテスト中は `false` のままにしておくのが
  おすすめです)
- 演出画面を外部モニターの正しい位置に表示したい場合は、`kiosk_window_position`
  に `"1920,0"` のような座標(外部モニターの左上座標)を設定してください。
  ノートPC画面の解像度や、外部モニターをどちら側に拡張しているかによって
  数値が変わります。分からない場合は空(`null`)のままにして、表示された
  ウィンドウを手動でモニター間ドラッグしてください
- Chrome/Chromiumが見つからない場合は既定のブラウザで演出画面だけを開きます
  (管理画面は手動で `/admin` を開いてください)

開発用に `scripts/start_bikkurapon.bat`(Windows)/ `scripts/start_bikkurapon.sh`
(Mac/Linux)もありますが、これは環境構築とサーバー起動をするだけのショートカット
です(ブラウザはサーバー自身が開きます)。

### XIAO ESP32-C3側(ファームウェア、USB接続版)

1. Arduino IDEに以下をインストール
   - ボード: esp32(Espressif Systems)のボードパッケージから `XIAO_ESP32C3` を選択
   - Tools > USB CDC On Boot を `Enabled` にする(USB経由のシリアル通信に必須)
   - ライブラリ: `ESP32Servo`
2. `firmware/xiao_esp32c3_usb_serial/xiao_esp32c3_usb_serial.ino` を書き込む
   (WIFI設定などは不要。ピン番号を変える場合だけ冒頭の定数を編集)
3. USBケーブルでノートPCに接続する。シリアルモニタでコイン検知ログを確認できます

WiFi接続版を使う場合は `firmware/xiao_esp32c3_wifi_http/` の冒頭にある
`WIFI_SSID`、`WIFI_PASSWORD`、`SERVER_URL`、`DEVICE_TOKEN` を設定してください。
さらに、`config/settings.json` で次の3つを変更する必要があります
(既定では安全のため、このPC自身からの接続しか受け付けません)。

- `"host": "0.0.0.0"` … 他の機器(ESP32)からつなげるようにする
- `"allow_remote_insert_coin": true` … ESP32からの `/api/insert_coin` を許可する
- `"device_token": "16文字以上の推測されにくい文字列"` … ファームウェアの
  `DEVICE_TOKEN` と完全に同じ値にする

### インターネットなしのルーター/APで使う手順

1. ルーターのDHCP機能を有効にし、ノートPCとESP32を同じSSIDへ接続する。
   ゲストWiFiや「AP/クライアント分離」は、端末同士の通信を遮断するため使わない
2. ノートPCで `ipconfig` を実行してIPv4アドレスを確認し、ESP32の
   `SERVER_URL` を `http://<そのIP>:5000/api/insert_coin` にする
3. 上記の`host`・`allow_remote_insert_coin`・`device_token`を設定してアプリを再起動する
4. Windowsファイアウォールの確認が出たら「プライベートネットワーク」を許可する
5. インターネット回線(WAN)は接続しなくてよい。ブラウザ用Socket.IOも
   `static/vendor/`から読み込むため、演出・管理画面を含めてLAN内で完結する

USB版を使う場合は変更不要です。

## 景品・確率のカスタマイズ

`config/prizes.json` を編集します。既定では「当たり」「はずれ」の2種類で、
**どちらを引いても必ずカプセルが1個出ます**(当たりは良い景品、はずれは
参加賞的な景品、という2ホッパー構成のため)。

```json
{
  "id": "atari",
  "name": "当たり",
  "probability": 0.2,
  "stock": 30,
  "hopper": "a"
}
```

- `probability` … 各景品の当選確率(全景品の合計が1.0になるようにしてください)
- `stock` … 初期在庫数。`null` にすると無制限
- `hopper` … 排出に使うホッパー記号(`"a"` = 当たり用、`"b"` = はずれ用)。
  `null` にするとカプセルを排出しない(在庫を用意しない「完全ハズレ」を
  追加したい場合などに使える)

在庫が0になった景品は自動的に抽選対象から除外され、残りの景品の確率だけで再抽選されます。

**全景品の在庫が尽きたとき**: 抽選はエラー扱いになり、在庫は減らさずカプセルも
排出しません(ESP32には `NONE` を返します)。演出画面は
「巫女さんを呼んでください」画面に切り替わり、管理画面などで在庫が補充される
まで表示し続けます(補充すると自動で待機画面に戻ります)。この状態でコインを
入れたお客さんへの対応(メダルの返却など)は、巫女さんが行う運用を想定しています。
`stock: null`(無制限)の景品を1つ用意しておけば、この画面は出ません。

初期在庫を変更した場合は `data/stock.json` を削除してから再起動すると、
`prizes.json` の内容で作り直されます。

**インストーラーで入れ直しても管理画面の内容が変わらない場合**

インストーラー(`.exe`)は、実行ファイルの隣に `config/` フォルダが
無い時だけ既定の設定をコピーする仕組みです。`config/` フォルダは
アンインストール・上書きインストールをしても自動では消えないため、
昔のバージョン(「大当たり」があった頃など)の `config/prizes.json` が
そのまま残っていると、新しい `.exe` に入れ替えても中身が変わりません。
これは既定の景品構成(`hopper` フィールドを持たない古い形式)を検出したら
自動でバックアップ(`prizes.json.bak`)を取ってから最新の内容に差し替える
ように対応済みです。手動で直したい場合は、設定フォルダ
(`%LOCALAPPDATA%\Bikkurapon\config\prizes.json`。exeの隣に書き込める場合は
そちら)を直接削除してから起動し直しても構いません。

## 在庫管理画面

起動時に自動で開く管理画面(`http://localhost:5000/admin`)から、景品ごとの残数を確認・変更できます。
補充した分だけ数値を増やして「更新」を押すと即座に反映され、ゲーム画面側の抽選にも反映されます。

既定では、管理画面と在庫・確率を変更する操作は **このPC自身からしか使えません**
(会場のWiFiにつながった来場者に書き換えられないようにするため)。
スマホなど別の端末から管理画面を使いたい場合は、`config/settings.json` で
`"host": "0.0.0.0"` と `"allow_remote_admin": true` にして、
`http://<ノートPCのIP>:5000/admin` を開いてください。ただし、同じWiFiにつながっている
誰でも在庫を書き換えられる状態になるので、使い終わったら元に戻すことをおすすめします。

## 運用上の注意

- 実際の現金を投入させる形にすると景品交換を伴う抽選(いわゆる賭博)に該当するおそれがあるため、
  文化祭では現金の代わりに事前購入したメダル・チケットをコイン投入口に使う運用を推奨します。
- 演出の見た目(色・アニメーション)は `static/css/style.css` の
  `.state-atari` / `.state-hazure` を編集することで自由に追加・変更できます。
- 本番当日は `config/settings.json` の `show_debug_button` を `false` にしておくこと
  (画面のテストボタンが消えるだけで、このPC上からは `/api/insert_coin` は動きます。
  他の端末からは既定で拒否されます)。
- 本番前に、在庫を使い切った状態で「巫女さんを呼んでください」画面が出ること、
  補充すると待機画面に戻ることを一度確認しておくと安心です。
- 本番用ルーター/APはWANへつながなくても構いません。ノートPCのIPアドレスが
  変わらないよう、ルーター側でDHCP予約を設定するとより安定します。
